## 完成したGASコード

### Code.gs の主要機能

1. **sendAutoReply(e)** - フォーム送信トリガーで実行される関数
   - MailAppを使用してメール送信
   - E列で送信済みフラグ管理
   - エラーハンドリング完備
   - lastRowのズレ対策

2. **processUnsentRows()** - 未送信データの一括処理（手動実行用）
   - 過去の未送信データをまとめて処理
   - 各行ごとにエラーハンドリング
   - Gmail送信制限を考慮した待機処理

3. **testSendEmail()** - テスト送信（動作確認用）
   - トリガー設定前の動作確認

### 設計のポイント

#### 安定性・信頼性
- ✅ try-catchによる完全なエラーハンドリング
- ✅ 各行に送信済みフラグを記録（重複送信防止）
- ✅ メールアドレス検証（@の存在確認）
- ✅ シート存在確認
- ✅ 失敗時のエラーログ記録

#### lastRowのズレ対策
- ✅ getLastRow()で動的に最終行取得
- ✅ 各行に送信済みフラグを立てることで、lastRowがズレても再送信されない
- ✅ 空行チェック（lastRow < 2）

#### トリガー不発対策
- ✅ 「フォーム送信時」トリガーの使用
- ✅ トリガーが実行されなかった場合のために processUnsentRows() を用意
- ✅ エラー通知設定でトリガー実行失敗を検知

#### 大学のGoogle Workspace対応
- ✅ MailApp使用（GmailAppより制限が緩い）
- ✅ 送信制限に配慮した設計
- ✅ 実行ログによる追跡可能性

## 初心者向けの設置手順（簡易版）

### 1. フォームとスプレッドシートを連携

1. Googleフォームの「回答」タブ → 「スプレッドシートにリンク」
2. スプレッドシート作成（シート名「フォームの回答 1」を確認）

### 2. 列構成確認

| 列 | 内容 |
|----|------|
| A列 | タイムスタンプ |
| B列 | 名前 |
| C列 | メールアドレス |
| D列 | 内容 |
| E列 | 送信状態（自動追加）|

### 3. Apps Scriptエディタでコード設定

1. スプレッドシート → 「拡張機能」→「Apps Script」
2. 既存のコードを削除
3. `Code.gs`の内容を貼り付け
4. 保存

### 4. 初回テスト実行

1. 関数選択で「testSendEmail」を選択
2. コード内の`testEmail`を自分のアドレスに変更
3. 実行 → 権限承認
4. テストメール受信確認

### 5. トリガー設定

1. 左メニュー「トリガー」→「＋トリガーを追加」
2. 設定：
   - 実行する関数: `sendAutoReply`
   - デプロイ: `Head`
   - イベントソース: `スプレッドシートから`
   - イベントタイプ: `フォーム送信時`
   - エラー通知: `今すぐ通知を受け取る`
3. 保存

### 6. 本番テスト

1. Googleフォームから回答送信
2. スプレッドシートE列に「送信済み」表示を確認
3. 自動返信メール受信確認

## トリガー設定の具体手順

### トリガーとは
特定のイベント発生時にスクリプトを自動実行する仕組み

### 設定画面

```
┌─────────────────────────────────────┐
│ 実行する関数を選択                     │
│ [sendAutoReply ▼]                    │
├─────────────────────────────────────┤
│ 実行するデプロイを選択                 │
│ [Head ▼]                             │
├─────────────────────────────────────┤
│ イベントのソースを選択                 │
│ [スプレッドシートから ▼]               │
├─────────────────────────────────────┤
│ イベントの種類を選択                   │
│ [フォーム送信時 ▼]                    │
├─────────────────────────────────────┤
│ エラー通知設定                        │
│ [今すぐ通知を受け取る ▼]              │
└─────────────────────────────────────┘
          [保存]
```

### 重要ポイント
- ❌ 「編集時」や「変更時」は使わない
- ✅ 必ず「フォーム送信時」を選択
- ✅ エラー通知を有効化して問題を即座に検知

## よくある失敗ポイント

### 1. メールが届かない

| 原因 | 対策 |
|------|------|
| シート名が違う | 「フォームの回答 1」に統一 |
| トリガー未設定 | トリガー画面で確認・設定 |
| 権限未承認 | 初回実行時に承認必須 |
| メールアドレス空欄 | C列入力必須 |
| Workspace制限 | IT部門に確認 |

### 2. 同じメールが何度も送信

| 原因 | 対策 |
|------|------|
| 送信済みフラグ機能してない | E列確認 |
| トリガー重複 | トリガー画面で重複削除 |

### 3. lastRowのズレ

| 原因 | 対策 |
|------|------|
| 空行混在 | 空行削除 |
| 手動データ追加 | フォーム経由のみ使用 |
| **本コードでは対策済み** | 各行に送信済みフラグ |

### 4. トリガーが実行されない

| 原因 | 対策 |
|------|------|
| トリガー種類間違い | 「フォーム送信時」を選択 |
| スクリプトエラー | 実行数画面でログ確認 |
| フォーム連携切断 | フォームから再連携 |

### 5. 大学のWorkspaceで動かない

| 原因 | 対策 |
|------|------|
| Apps Script制限 | IT管理者に実行権限確認 |
| 外部メール制限 | IT管理者にMailApp許可依頼 |

### 6. エラーが分からない

#### 確認手順
1. Apps Script「実行数」をクリック
2. 失敗した実行をクリック
3. エラーメッセージ確認

#### 主なエラー
- `Cannot read property 'getValue' of null` → シート名間違い
- `Exception: Invalid email` → メールアドレス無効
- `Service invoked too many times` → 送信制限超過（1日100通）

## トラブルシューティング チェックリスト

問題発生時は以下を順番に確認：

- [ ] シート名が「フォームの回答 1」
- [ ] トリガーが「フォーム送信時」で設定済み
- [ ] 権限が正しく付与されている
- [ ] C列にメールアドレス入力されている
- [ ] 実行ログにエラーなし
- [ ] E列に「送信済み」または「送信失敗」表示あり
- [ ] testSendEmail が正常動作する

## 送信制限について

- **無料アカウント**: 1日100通まで（制限は変更される可能性があります）
- **Google Workspace**: 制限緩和あり
- **大量送信**: SendGrid等の外部サービス検討
- 最新情報: [Google Apps Script Quotas](https://developers.google.com/apps-script/guides/services/quotas)

このシステムは以下の要件を満たしています：

✅ **フォーム送信ごとに1通ずつ自動返信**

✅ **処理失敗しても他に影響なし（エラーハンドリング）**
✅ **トリガー設定方法を説明**
✅ **初心者でも動く安定構成**
✅ **2回目、3回目以降も必ず送信**
