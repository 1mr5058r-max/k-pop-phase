## 初心者向けの設置手順

### 1. Googleフォームとスプレッドシートの準備

1. Googleフォームを作成済みであることを確認
2. フォームの「回答」タブから「スプレッドシートにリンク」をクリック
3. 「新しいスプレッドシートを作成」を選択（すでに連携済みの場合はそのまま使用）
4. スプレッドシートが開いたら、シート名が「フォームの回答 1」であることを確認

### 2. スプレッドシートの列構成確認

以下の列構成になっていることを確認してください：

- **A列**: タイムスタンプ
- **B列**: 名前
- **C列**: メールアドレス
- **D列**: 内容
- **E列**: 送信状態（自動で追加されます）

### 3. Apps Scriptエディタを開く

1. スプレッドシートを開いた状態で、メニューから「拡張機能」→「Apps Script」をクリック
2. Apps Scriptエディタが新しいタブで開きます

### 4. コードをコピー

1. エディタに表示されている既存のコード（`function myFunction() {}`など）を全て削除
2. `Code.gs`ファイルの内容を全てコピー
3. Apps Scriptエディタに貼り付け
4. ファイル名を「Code.gs」に変更（左上のファイル名部分をクリック）
5. 「プロジェクト名」をクリックして、分かりやすい名前（例：「フォーム自動返信」）に変更
6. 💾マークをクリックして保存（またはCtrl+S / Cmd+S）

### 5. 初回実行と権限付与

1. エディタ上部の関数選択ドロップダウンから「testSendEmail」を選択
2. コード内の`testEmail`変数を自分のメールアドレスに変更
3. ▶実行ボタンをクリック
4. 「承認が必要です」というダイアログが表示されたら：
   - 「権限を確認」をクリック
   - Googleアカウントを選択
   - 「詳細を表示」をクリック（「安全ではないページ」という警告が出る場合）
   - 「（プロジェクト名）に移動」をクリック
   - 「許可」をクリック
5. 実行が完了したら、テストメールが届くことを確認

### 6. トリガーの設定

1. Apps Scriptエディタ左側のメニューから「トリガー」（時計マーク⏰）をクリック
2. 右下の「＋トリガーを追加」ボタンをクリック
3. 以下の設定を行います：

   **実行する関数を選択:**
   - `sendAutoReply` を選択

   **実行するデプロイを選択:**
   - `Head` を選択

   **イベントのソースを選択:**
   - `スプレッドシートから` を選択

   **イベントの種類を選択:**
   - `フォーム送信時` を選択

   **エラー通知設定:**
   - `今すぐ通知を受け取る` を選択（推奨）

4. 「保存」をクリック
5. 権限の確認を求められた場合は、手順5と同様に権限を付与

### 7. 動作テスト

1. 実際にGoogleフォームから回答を送信
2. スプレッドシートの「フォームの回答 1」シートを確認
3. E列に「送信済み」と表示されることを確認
4. 指定したメールアドレスに自動返信メールが届くことを確認

## トリガー設定の具体手順（詳細版）

### トリガーとは
トリガーは、特定のイベント（フォーム送信など）が発生したときに、自動的にスクリプトを実行する仕組みです。

### 設定手順

#### ステップ1: トリガー管理画面を開く
1. Apps Scriptエディタを開く
2. 左側のメニューから「トリガー」（時計マーク⏰）をクリック

#### ステップ2: 新しいトリガーを追加
1. 画面右下の「＋トリガーを追加」をクリック
2. トリガー設定ダイアログが表示される

#### ステップ3: 各項目を設定

| 設定項目 | 選択する値 | 説明 |
|---------|-----------|------|
| 実行する関数を選択 | `sendAutoReply` | フォーム送信時に実行される関数 |
| 実行するデプロイを選択 | `Head` | 最新のコードを実行 |
| イベントのソースを選択 | `スプレッドシートから` | スプレッドシートのイベントをトリガーにする |
| イベントの種類を選択 | `フォーム送信時` | フォームが送信されたタイミングで実行 |
| エラー通知設定 | `今すぐ通知を受け取る` | エラー発生時に即座にメール通知 |

#### ステップ4: 保存と権限付与
1. 「保存」をクリック
2. 権限の承認を求められた場合は、手順5の権限付与を実施
3. トリガー一覧に新しいトリガーが表示されることを確認

### トリガーの確認方法
- トリガー画面で、設定したトリガーが表示されているか確認
- 「フォーム送信時」と表示されていればOK

### トリガーの実行履歴確認
1. 左側のメニューから「実行数」をクリック
2. トリガーが実行された履歴とステータスを確認できる

## よくある失敗ポイント

### 1. **メールが届かない**

#### 原因と対策：

**シート名が違う**
- シート名が「フォームの回答 1」でない場合、コードは動作しません
- シート名を確認して、コード内のシート名と一致させてください

**トリガーが設定されていない**
- トリガー画面で「フォーム送信時」のトリガーがあるか確認
- ない場合は「トリガー設定の具体手順」を参照して設定

**権限が付与されていない**
- 初回実行時に権限の承認が必要です
- 「承認が必要です」というダイアログが表示されたら、必ず承認してください

**メールアドレス列が空**
- C列（メールアドレス）が空欄だと送信されません
- フォームに「メールアドレス」を入力する項目があるか確認

**大学のGoogle Workspaceの制限**
- 一部の大学では外部へのメール送信が制限されています
- IT部門に確認して、MailAppの使用が許可されているか確認してください

### 2. **同じメールが何度も送信される**

#### 原因と対策：

**E列の「送信済み」フラグが機能していない**
- E列に「送信済み」が正しく記録されているか確認
- 手動でE列を編集していないか確認

**トリガーが複数設定されている**
- トリガー画面で同じトリガーが複数ないか確認
- 重複している場合は、古いトリガーを削除

### 3. **lastRowのズレ**

#### 原因と対策：

**空行が混在している**
- シート内に空行があると、lastRowが正しく取得できません
- 空行を削除してください

**手動でデータを編集している**
- フォーム送信以外でデータを追加している場合、ズレる可能性があります
- フォーム経由でのみデータを追加してください

**このコードでは対策済み**
- `getLastRow()`を使用して最終行を取得
- 各行に送信済みフラグを立てることで、ズレても再送信されません

### 4. **トリガーが実行されない**

#### 原因と対策：

**トリガーの種類が間違っている**
- 「編集時」や「変更時」ではなく、「フォーム送信時」を選択してください
- トリガー画面で確認・修正

**スクリプトにエラーがある**
- 実行数画面でエラーログを確認
- エラーメッセージに基づいて修正

**スプレッドシートとフォームの連携が切れている**
- フォームの「回答」タブで、スプレッドシートへのリンクが有効か確認
- 必要に応じて再連携

### 5. **大学のGoogle Workspaceで動かない**

#### 原因と対策：

**Apps Scriptの実行が制限されている**
- 大学のポリシーでApps Scriptが制限されている場合があります
- IT管理者に連絡して、Apps Scriptの実行権限を確認

**外部メール送信が制限されている**
- 大学外のメールアドレスへの送信が制限されている場合があります
- IT管理者に連絡して、MailAppの使用を許可してもらってください

**代替案: GmailAppの使用**
- MailAppがどうしても使えない場合、GmailAppに変更することも検討
- ただし、要件では MailApp を使用することと指定されています

### 6. **エラー通知が来るが原因が分からない**

#### 対策：

**実行ログを確認**
1. Apps Scriptエディタの「実行数」をクリック
2. 失敗した実行をクリック
3. エラーメッセージを確認

**Logger.logを確認**
1. エディタ上部の「実行ログ」をクリック
2. どこでエラーが発生しているか確認

**よくあるエラーメッセージ**
- `Cannot read property 'getValue' of null` → シート名が間違っている
- `Exception: Invalid email` → メールアドレスが無効
- `Service invoked too many times` → Gmail送信制限に達した（1日100通まで）

## 補足：未送信データの一括処理

過去にフォーム送信されたが、メールが未送信のデータを一括処理したい場合：

1. Apps Scriptエディタで関数選択ドロップダウンから「processUnsentRows」を選択
2. ▶実行ボタンをクリック
3. E列が空白、または「送信失敗」となっている行に対してメールを送信
4. 実行ログで処理結果を確認

**注意**: Gmail送信制限（1日100通）に注意してください。

## メンテナンスとカスタマイズ

### メール本文のカスタマイズ

`Code.gs`の以下の部分を編集することで、メール本文を変更できます：

```javascript
const subject = 'フォーム送信を受け付けました'; // 件名

const body = 
  name + ' 様\n\n' +
  'フォームへのご回答ありがとうございます。\n' +
  // ↑ この部分を編集
```

### 送信制限について

- **MailApp**: 1日あたり100通まで（無料アカウント、制限は変更される可能性があります）
- Google Workspaceアカウントは制限が緩和されます
- 最新の制限については[Google Appsスクリプトの割り当て](https://developers.google.com/apps-script/guides/services/quotas)を確認してください
- 大量送信が必要な場合は、SendGrid等の外部サービスを検討

### セキュリティ対策

このコードには以下のセキュリティ対策が含まれています：

1. メールアドレスの検証（@を含むかチェック）
2. エラーハンドリング（try-catch）
3. 送信済みフラグによる二重送信防止
4. MailAppの使用（GmailAppより安全）
